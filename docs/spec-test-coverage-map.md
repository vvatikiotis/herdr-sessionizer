# SPEC-to-test coverage map

Audit tip: `247c192` (`test/full-spec-coverage`), confirmed as the current merge tip before this audit. The Rust suite contains **47 test methods** (24 `tests/commands.rs`, 16 `tests/directory_config.rs`, 1 `tests/manifest.rs`, 3 `tests/shell_pool.rs`, 3 `tests/workspace_exit.rs`). `cargo test --all-targets` and `cargo test --release --all-targets` each passed all 47. `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, and `cargo build --release` passed. All three isolated live scripts passed freshly on macOS with bounded waits: `tests/live_picker.py`, `tests/live_config_error.py`, and `tests/live_workspace_exit.py`.

This is an audit artifact only. It does not change the product or `SPEC.md`.

## Evidence rules

- **Candidate stream** means a stub captured the rows or reload input. It does not prove that fzf rendered, highlighted, or accepted that identity.
- **Rendered/accepted identity** means the real-fzf PTY observed the visible row, or the accepted action/output proved which row was selected.
- **Fresh live pass** means the isolated script passed during this audit on the current macOS host. Historical references in the table are retained only where the test name or prior evidence is being described.
- **Static manifest** means direct inspection of `herdr-plugin.toml`; it is not evidence that Herdr delivered the registered event.
- Status is `covered`, `partial`, `missing`, or `environment-limited`. A historical pass is not treated as a current rerun.

## Remaining approved slices

The current audit is not a full-coverage pass. These are the smallest remaining gaps, stated as partial or missing evidence rather than environment limitations. They are not new requirements.

The #13 discovery, #14 navigation/pool, #15 manifest, and #16 real-fzf slices are represented by the current 47-test Rust suite and the three fresh live scripts. This is not a full-coverage claim. The remaining partial IDs are `SOL-06`, `US-19`, `US-23`, `US-34`, `RT-01`, `DIR-07`, `DIR-08`, and `NAV-02`. The explicit platform limitation is recorded separately in `PLAT-02`.

The remaining evidence gaps are direct history-refresh ordering and permission-denied symlink-target coverage. `PLAT-02` records the last item as an explicit macOS host limitation, not as a pass. No requirement is reclassified as an environment limitation merely because its assertion is missing.

No product or specification change is authorized by these gaps. No deployment, push, or main-branch change is part of this audit.
